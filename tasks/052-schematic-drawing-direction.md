## 1. 结论

现在可以进入原理图绘制。五类局部编辑、ChangePlan、多窗口路由、器件事实、真实引脚回读和审查链提供了执行基础。
主要缺口是**电路含义到人类可读图纸的转换**。推荐做“带电路语义的原理图编译器”，将画法、坐标、走线和可读性检查交给工具。

首个产品流程：指定功能和关键条件 → 生成一块可读的电路 → 查看依据和待确认项 → 应用 → 局部修改保持版式。
继续聚焦原理图，PCB 自动布局布线不进入此阶段。

工具可以保证明确的制图规范，不能保证任何人对任意电路都觉得好看。因此验收同时需要机器检查和工程师读图任务。
当前仓库主要面向 EasyEDA Pro；若仍保留早期 Altium 目标，电路/画法层保持宿主独立，本阶段不同时开发两个后端。

## 2. 审查侧需要收口的三个问题

### 2.1 MPN 冲突不是修改 Value 的充分依据

`src/boardwise/rules/params.py:359` 的 FindingTarget 仍将 MPN 解码值写入 suggested_after。
但 048 最新裁决明确：17 颗器件是 MPN 字段写错，而不是设计值应该改成 MPN 对应值。
依据见 PROGRESS 的 048 收官记录、`tasks/048-decoder-numeric-exponent.md`。

应分开记录“发现矛盾”和“怎么修”：改 Value 或重选 MPN/LCSC 都可以是候选，由设计意图、手册和核实过的商品事实决定方向。
依据不足时保留待确认，不能默认改电气参数。警告消失仅证明两个字段一致，不证明原电路意图得到满足。
此前建议直接按 MPN 修改阻值的示例也需要按此纠正。

当前 R 的 3 倍、C 的 25 倍幅度容忍，以及模糊编码取最接近板值的读法，是项目噪声策略，不是采购数据准确的证据。
建议分别记录事实 observation、策略 policyDecision、修复候选 repairCandidates。新生成 BOM 优先用精确核实的器件事实。
LED 电阻窗口、去耦组合等经验也应保留适用条件，不扩大成普遍电气规律。

## 4. 架构：三份数据，一条编译管线

```text
需求与工程师约束
  → 模型提出 CircuitSpec + PresentationSpec，器件/配方事实核验
  → 解析真实符号几何，实例化画法语法
  → 模块布局/布线候选
  → 硬约束过滤 → 电路表达/可读性分层排序
  → LayoutPlan + 对应预览 + 检查证据
  → 按现有 ChangePlan 授权策略执行
  → 实际引脚校准、网表/几何回读、最终渲染检查、保存确认
```

**CircuitSpec：电路是什么。** 稳定逻辑器件 ID、型号/符号、参数、网络成员集合、引脚、显式 NC、开放接口、工作条件、依据。
位号与宿主 primitiveId 分开。pairwise connections 可作输入糖，内部归一化成一网多个引脚，记录页/工程作用域。
“没给连接”不等于 NC。回读比较网络成员分区与命名语义，不能只比较会变化的自动网名字符串。
器件事实核实、配方条件满足、工程师确认和模型提案分别记录状态；电气依据未确认的输出只能是明确标注的草稿。

**PresentationSpec：怎样让人看懂。** 功能模块和外围归属、主路径/反馈路径、端口角色、画法选择、局部直连义务、标签策略、
侧别偏好、用户锁定、文字样式。同一网表有许多电气等价画法，这一层使工具知道哪种表达符合意图。
默认模型入口不接受原始坐标、wire points 和 connector 动作；工程师显式锁定或手工编辑仍有合法入口。

**LayoutPlan：工具算出的图。** 实际符号版本/几何哈希、合法姿态、位置、线段、junction、网标、电源符号、文字位置、
目标快照、源 Spec 哈希和验收证据。预览绑定具体计划。
落地后的引脚偏差只能在已有约束内做有限校准；实质版式改变则旧预览失效，重新检查。

这是模块/dataclass 的职责划分，不要求重写仓库或拆微服务。

## 5. 最重要的新资产：画法语法

每种语法描述角色、相对关系、必须可见的拓扑及允许变体；坐标由真实符号、文字和空间计算。

| 语法 | 工具执行的表达关系 |
|---|---|
| 分压 | 两电阻竖排，中点抽头引出，上下网络方向明确，关键关系直接连线 |
| RC 低通 | 输入—R—输出主干，C 从输出节点向地分支，不靠远处标签拼读局部拓扑 |
| LDO | 输入、输出分侧；各自电容归各自节点；地表达一致；文字独立占位 |
| 后续反馈模块 | 保留可辨认的回授通道，不强行把反馈展开成无环的左到右图 |

这不是为每颗芯片存一张固定坐标图。换真实符号、长文字、加支路后，语法仍应成立。
通用 graph layout 可辅助模块排布，但不能自行分辨去耦、滤波和反馈。GND/公共电源不能按普通吸引边把无关器件聚在一起。
关键局部拓扑优先直连；跨模块、跨页、高扇出允许按策略用真实标签。普通文字不产生电气连接，真实标签仍需网表核对。

SymbolProfile 包含 body、pin tip/朝向、允许姿态、文字边界和角色映射。
库符号不合适时选引脚映射已核实的兼容符号或报告能力边界，不能换脚号迁就版式。
原理图中的去耦接近供电脚表达归属，不证明 PCB 的实际回路面积和寄生电感合格。

## 6. 可读性合同

| 类型 | 示例 | 处理 |
|---|---|---|
| 硬约束 | 网络/NC 一致；实际线端接实际引脚；无意外 junction；不穿无关器件；文字无非法遮挡；不越页/禁区；遵守用户锁定 | 违规不交付为合格布局 |
| 画法约束 | 分压抽头直接可见；RC 电容归属输出；反馈通道；模块接口/标签政策 | 由适用语法决定，例外要显式 |
| 优化目标 | 无连接交叉、折点、绕行、对齐、间距、留白、局部修改引起的位移 | 合格候选中分层排序 |

模块边界允许从声明端口穿越；开放接口和显式 NC 不是非法悬空。
“所有线不能交叉、所有地必须朝下、所有信号必须从左到右”都不适合当全局铁律。

排序层级：合法性 → 电路表达 → 可读性 → 紧凑程度。
各层可用固定权重，但不应允许少几毫米线长抵消关键拓扑难辨。
保留原始指标和具体原因，不能只报 aesthetics=4.2。

第一版采用有限合法姿态、间距和路由顺序，确定性搜索和稳定 tie-break 即可。
未找到合格候选时报告具体冲突及可选动作：扩大区域、放宽锁定、选兼容符号等。
有限搜索失败只能说当前能力/预算内未找到解，不能证明数学无解。
程序负责可计算约束，视觉模型补充发现遗漏，工程师读图测试验证整体可用性。

## 8. 推荐实施顺序

| 阶段 | 交付物 | 出口 |
|---|---|---|
| A 最小合同 | 两份 Spec、SymbolProfile、独立检查接口、参考图/预期连接；审查三项收口 | 输入与正确/可读的定义一致 |

| D 组合/增量 | CH340G 完整模块、多模块端口与标签、局部编辑 | 改一处不全页重排，保留人工锁定，集成电路完整 |
| E 产品验证 | 不同模型用同一工具、工程师盲读、成本统计 | 首次可接受率、读图正确率/耗时、人工返工和端到端成本可量化 |

用例从 A 定义，B 起持续执行；E 不是最后才开始看美观。不以 API/模板数量衡量完成。

第一批建议约 12 个离线场景：三种语法、不同符号尺寸和脚向、长文字、附加支路、狭窄区域及故意错误输入。
固定正确 CircuitSpec 测编译器；自然语言需求另测模型生成 Spec，避免混淆电气推理和布局错误。
参考图坐标不能喂给生成器后再宣称自动布局成功；预期网络独立指定，短路/错脚/NC 被接/压字负例应被独立检查器检出。
合格输出硬违规为零，另报成功率，将拒绝和超时计入分母，防止全拒绝拿零缺陷。
可暂定支持范围内普通任务首次可接受率 ≥90%、工程师评价中位数 ≥4/5，先用人工参考流程校准；这些是建议目标，不是现有成绩。

邀请 2–3 位工程师盲看：分压抽头在哪、RC 输入到输出怎么走、某电容属于哪一路电源。
记录答对率、时间和修到可接受图纸的分钟数，风格喜好评分作为补充。
固定输入与版本稳定复现，仅改值尽量只调整相关文字和局部空间。

## 9. 降低模型门槛的验证

工具能减少模型的空间推理、像素纠错和工具试错，不能替代电路设计知识和器件事实。
几何层稳定后，用同样需求、事实和工具比较模型，统计每个可接受结果的费用、时间、重试、人工修订。
低价模型通过已有配方完成日常模块，强模型处理复杂意图与异常，才算验证了产品主张。
