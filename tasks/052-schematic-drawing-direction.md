# 052 · 原理图绘制方向评审与 M4 路线

日期：2026-09-27

状态：方向建议。依据当前 `051-schematic-drawing-DRAFT.md`、016/029/035/036/037
的局部修改链路、017/049 的审查评测，以及现有 `layout.py`、`subcircuit.py`、
`portmeta.py` 和 `changeplan.py` 实现整理。本文不改变既有代码行为。

## 一、结论

Boardwise 已经具备开始做原理图绘制的基础：模型可以输出声明式计划，工具可以校验
器件与引脚、计算落点、正交布线、执行、回读、保存和重新审查。方向是对的。

需要修正的是“人类审美”的架构位置。它不能只放在后续的审美评分切片，也不能靠
`layoutHint` 或提示词让模型记住若干坐标习惯。绘制入口就应当把以下三件事拆开：

1. **CircuitSpec**：电路必须是什么，包含器件、引脚、网络、NC、参数和证据。
2. **PresentationSpec**：图纸应怎样表达，包含功能分组、信号流、端口侧别、锚点、
   电源/地位置、标签策略和用户锁定项。
3. **LayoutPlan**：工具根据前两者和真实符号几何计算出的具体落点与走线。

模型只负责提出前两者的候选；工具负责规范化、布局、布线、硬约束检查、候选排序、
落地和回读。模型永远不直接生成 connector API 调用，也不直接提交 x/y 坐标。

## 二、当前草案中需要调整的地方

### 1. `ModulePlan.connections` 不应成为唯一电路真相

当前草案用 `U1.4 -> net:VCC`、`C1.1 -> U1.4` 表达连接，适合演示，但作为长期
协议会遇到几个问题：

- 同一网络的多个引脚被表示成一串边，网络身份和成员集合不够明确；
- 跨模块、跨页和电源网需要稳定的 net identity，而不是依赖边的排列顺序；
- NC、明确悬空、自动网名和用户命名网无法用同一种边表达；
- 工具很难区分“模型想连接”与“工具为了布线而选择的中间点”。

建议保留 `connections` 作为输入兼容层，进入编译器后立即规范化为：

```json
{
  "nets": [
    {"id": "VCC", "class": "power", "members": ["U1.4", "C1.1"]},
    {"id": "GND", "class": "gnd", "members": ["C1.2"]}
  ],
  "nc": ["U1.5"],
  "openPins": []
}
```

验收和回读都针对规范化后的 pin→net/NC 映射。线段、标签和旗标只是表达方式，不能
反过来改变电路真相。

### 2. `layoutHint` 不足以表达可读图纸

`flow` 和 `groups` 只表达了很少的布局意图。至少还需要：

- 组件的功能角色：`source`、`core`、`load`、`filter`、`feedback`、`interface`；
- 输入、输出、电源、地、反馈端的首选侧别；
- 模块锚点和相对关系，例如“去耦靠近供电脚”“反馈回路短且不穿越主信号”；
- 允许的标签/旗标策略；
- 用户锁定的位置、方向和不可穿越区域；
- 证据来源与置信等级。

这些字段属于 `PresentationSpec`，不应混进器件事实或电气连接表。

### 3. “审美闭环”不应排到第四片才出现

先生成很多图，最后再评分，会产生大量不可读资产，也会让布局器针对错误目标优化。
第一片就应执行最小可读性门禁：器件不重叠、线不穿器件、无无意义折返、主信号流
可辨、值和位号不互相覆盖、网络名可追踪。

第四片可以做视觉迭代和人工评分，但它应当是已有约束的加强版，而不是第一次引入
可读性。绘制管线从第一天就要保存每个候选的 `hard_violations`、`soft_score` 和
各轴证据。

### 4. “AI-asserted 连接”不能和核验过的配方同等呈现

草案允许配方外连接“照画但在报告中点名”。这适合探索模式，但不应直接进入“完成”
状态。建议分三种状态：

- `verified_recipe`：器件事实和配方均有来源，工具可自动验证；
- `engineer_confirmed`：模型提出、工程师确认，工具验证几何和网表；
- `ai_asserted`：只完成结构和几何验证，电气语义仍待确认。

第三种可以生成草稿，但页面和报告必须明显标记为未确认，不能显示成绿色通过，也不能
作为后续模块的无条件事实输入。

### 5. CH340G 适合作为回归夹具，不足以证明方向成立

CH340G USB-UART 是很好的第一个垂直切片：事实完整、规模适中、现有回放资产多。
但如果只在它上面调布局，最终很可能得到“CH340 专用绘图器”。第一片通过后，至少再
加入一个不同拓扑和不同符号形状的模块，例如 LDO 电源模块或 RC/分压模块；目标不是
做很多器件，而是验证同一布局合同能跨符号几何复用。

## 三、推荐的绘制编译管线

```text
需求 / 已有模块 / 可选手册
        ↓
模型提出 CircuitSpec + PresentationSpec
        ↓
schema + 器件 facts + 引脚存在性 + 电气配方校验
        ↓
规范化 pin→net/NC IR
        ↓
语义布局：角色、侧别、锚点、阅读顺序、分组
        ↓
几何布局：真实符号 bbox、网格、keep-out、通道
        ↓
候选布线：正交、最少交叉、短线、少折点、端点明确
        ↓
硬约束门禁 + 可读性评分 + 候选排序
        ↓
预览报告 / render
        ↓
用户授权 → apply → 活网表/几何回读 → review → save
```

现有 `layout.py` 的网格、bbox、正交 BFS 和标题栏避让可以继续用。它们应当成为
LayoutPlan 的执行器，而不是让模型重新决定坐标。`subcircuit.py` 的“放置后读取真实
引脚再布线”也应继续作为所有新模块的强制规则。

## 四、把“人类可读”编成工具约束

### 硬约束

以下任意一项失败，都不允许把候选标为可应用：

- 器件、引脚、文字和标题栏的非法重叠；
- 线穿过器件 body 或错误的 pin tip；
- 对角线、悬空线、重复线、错误网络端点；
- 线端落在异网线段上产生意外 junction；
- 网络成员与 CircuitSpec 不一致；
- NC 被连接，或必接脚没有连接；
- 值、位号、网络名和关键说明文字不可读或互相覆盖；
- 走线越过模块边界、keep-out 或用户锁定对象；
- 关键电源/地没有明确的表达方式。

### 可优化目标

在硬约束通过的候选中，按固定权重排序。第一版不需要机器学习，确定性评分就够：

| 轴 | 可计算指标 |
|---|---|
| 拓扑可辨 | 关键模块的图结构与预期配方一致，关键关系是否被长线/标签遮蔽 |
| 流向明确 | 输入到核心到输出的横向单调性，主路径反向次数 |
| 分组合理 | 同一功能块的包围盒、跨组边数量、外围归属距离 |
| 布线简洁 | 总线长、折点数、平行走线重叠、绕行次数、交叉数 |
| 文字可读 | 最小文字间距、位号/值遮挡、标签方向、同网名一致性 |
| 电源表达 | 电源集中程度、地回路方向、去耦到供电脚的距离 |

分数必须保留原始指标和扣分原因。不要只输出一个 `aesthetics: 4.2`，否则模型和人
都无法知道下一步该修什么。

### 语义排序比几何微调更重要

推荐默认阅读顺序：

```text
外部输入 → 保护/接口 → 核心器件 → 滤波/反馈 → 外部输出
电源从上方或左上进入，地从下方回收，旁路器件贴近供电脚
```

这不是全局绝对规则。对于反馈、时钟、差分和高扇出网络，使用专门模板覆盖默认
流向；没有模板时报告偏离原因，不让通用布局器默默“优化”掉电路意图。

## 五、AI 与工具的边界

模型可以决定：

- 需求对应的模块和器件候选；
- 功能角色和模块边界；
- 网络命名和需要工程师确认的例外；
- 选择哪个已验证配方，以及参数值候选。

工具必须决定：

- 引脚号是否存在，器件事实是否可用；
- 每个 pin 的唯一网络归属；
- 具体落点、端口侧别、网格和 keep-out；
- 线怎么走、是否会产生 junction 或穿越；
- 回读是否满足计划，复查是否减少问题，保存状态是什么。

模型若输出坐标、connector action、原始 wire points 或“已通过”的结论，schema 应
直接拒绝，而不是尝试清洗后继续执行。

## 六、M4 的推荐切片

### Slice A：单模块编译器

输入一个 5–10 器件的 ModulePlan，输出规范化 CircuitSpec、PresentationSpec 和
LayoutPlan。先做 CH340G USB-UART，保持空白 `bw_draw` 页、预览、应用和删除流程。

验收重点：同一计划重复应用零写入；旧快照拒绝；活网表逐脚一致；规则复查没有新增
高优问题；render 图中不出现硬约束违规。

### Slice B：同一电路、两种符号几何

使用相同的功能拓扑，替换至少一种真实符号或旋转方向。目标是证明布局器消费的是
pin geometry + role metadata，而不是一套固定坐标。加入一个 AMS1117 或 RC/分压模块，
不要只复制 CH340 数据。

### Slice C：候选布局与确定性评分

对同一 CircuitSpec 生成 3–8 个候选：改变核心位置、外围侧别和通道路由顺序。先过硬
门禁，再按上述可读性指标排序。保存 winner、落选候选和每项扣分，保证失败可解释。

### Slice D：多模块同页

先放模块框和锚点，再做模块间网络；禁止把所有器件扁平化后一次 shelf-pack。模块间
连接使用明确的端口和网络接口，长连接采用标签策略，不能用一条跨页长线掩盖分组。

### Slice E：小规模人工评测

至少 3 位熟悉原理图的工程师，盲看候选图，按五轴 1–5 分并记录“第一次看懂该模块
需要多久”。同时记录硬约束失败率、网表失败率、人工移动次数和从草稿到可接受图的
分钟数。评测应包含 CH340、LDO、RC/分压和一个故意复杂的负例。

## 七、第一阶段不要做的事

- 不要先做任意原理图的一键生成；先做有限模块语法和失败可解释性。
- 不要让模型直接调整坐标来“修美观”；坐标搜索应在工具侧完成。
- 不要把单一视觉模型评分当作通过条件；图像评分必须与网表、几何和指标并列。
- 不要把标签当成真实连接；连接真相只能由 pin→net 和编辑器网表确认。
- 不要先做全局最优布局或通用模拟仿真；模块模板、通道和局部候选足够支撑第一版。
- 不要为了覆盖更多芯片而快速扩 facts；优先把少量器件的引脚几何、配方和画法验证完整。

## 八、M4 的完成定义

M4 第一阶段完成，不是“能画出一张图”，而是下面的合同全部成立：

1. 模型输出不含坐标和 connector 调用；
2. 工具可从输入生成稳定的 CircuitSpec/PresentationSpec/LayoutPlan；
3. 硬约束零违规；
4. 活网表与计划逐脚一致；
5. 至少两个不同模块或符号形状通过；
6. 重新应用幂等，旧计划和焦点错误会拒绝；
7. 评测者能在短时间内看懂功能分组和信号流；
8. 失败报告指出是事实缺失、电路不合法、布局无解还是表达质量不足。
