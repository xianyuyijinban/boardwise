## 1. 528A：`update-connector --no-reload`（R4-C 的前半）

**依据**：R4 实验④（2026-10-17 真机，岳亲手点菜单）：写共享记录后**不 reload**、只点一次扩展菜单，
test 窗 instance 更换且 `bridge status` 报 `0.5.14-r4probe` ⇒「免重载热更」在用户态已是
**「写 + 点一次菜单」**。stub 只剩「连菜单都不用点」的增量，而它要换来的是在**无认证 WS 上执行
远端载荷**的风险（`outputs/R4/design-proposal.md` §1/§3b）。

**要做的**：
- `bridge update-connector` 新增 `--no-reload`（或 `--reload/--no-reload` 成对）：只写存储记录，
  不派发 reload；退出码语义沿用 020/025 的「写成功 ≠ 已激活」，**明确打印**
  「已写入，未激活：点一次扩展菜单即生效（不需要重载编辑器）」。
- 默认行为**不变**（仍写 + reload），否则现有脚本与文档全要改，且 `verified` 的等待逻辑依赖 reload。
- 文档：`docs/bridge.md` command 表 + `SKILL.md` 的 update-connector 行；说明两条路各自何时用
  （有未保存状态 → `--no-reload`；无 → 默认）。
- 测试：写记录不派发 reload（假 connector 计数）、退出码、提示文案、默认路径不变。

**验收**：真机一次（`test` 窗）：`--no-reload` → 版本未变、点菜单 → 版本变、全程无 reload。

## 3. 527D3 + 527D2（0.6.0 阻塞项）

**527D3（设计活）**：`entry.category` 有 14 处直读绕过 `shelf_declaration`
（`rules/pcb/mcureset` / `mcusupply` / `crystal` / `regulator` / `fbplacement` / `foc` /
`focground`、`rules/params` / `paramspec` / `decap` / `archclosure` / `railratings`、
`core/architecture` / `power_domains`）。
- 修法：新增分档感知入口（例如 `partkind.declared_category(entry, *, allow_machine)`
  或给每个读点传规则的 `REQUIRES_HUMAN_VERIFIED`），并**逐条判定**该规则属于「数字」还是「结论」；
- 判据：机器授的分类对「结论类」规则一律不可见，对「算数字」的可见；每条读点都要有
  一条「机器档 vs 人签档」两态断言；
- 风险：会动 190/192 的判型锚，必须重钉 `test_126a` 指纹并跑 14 块夹具对拍。

**527D2（小活）**：`parts classify --from/--page/--quote` 的证据**不落货架**，导致
`machine_verified` 的分类事后追不到页码。修法：把证据写进该条目的 `provenance`/`notes`
（或新增 `category_provenance`），并同步改「只改两个键」那条约束的措辞与对应测试。

## 4. 529：191D 分类空白带（数值不动）

**问题**：`HF_FARADS ≤ 1µF`、bulk `≥ 10µF`，中间 **2.2µF / 4.7µF 全落 `unknown`**——而这正是
最常见的输入陶瓷滤波值。实测后果：毕设FOC PCB1 上 `U11@+5V` / `U13@+5V` 的 2.2µF×3 被判
「输入侧没有滤波」，三条假 WARN（191D 因此把「输入侧无电容」收窄成「一个候选都没有」）。
**这是分类器的空白，不是板子的问题。**

**要做的**：先量（五块夹具 + 实板A 上有多少 `unknown` 电容、按值分布），再定是「把 2.2–4.7µF
划进 HF（并按容值给不同的距离档）」还是「新增第三档 mid」，然后**撤销 191D 的那个收窄**
（收窄是为绕过空白带，空白带补上后该恢复成按电容计数）。判据：同一批板子上假 WARN 归零，
且原来真实缺滤波的板子仍然出声。
