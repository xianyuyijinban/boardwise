# 069：同角色远脚不连实体线——各引短线打同名旗标（岳手绘示例定法）

## 来源（岳原话）

## 地面真值（主代理已从 P22 几何逐根线解出，证据 `outputs/069_ldo_example/`）

岳在 test 工程 P22 下半页手绘了 U1 AMS1117-3.3 示例（`p22_yue.png` 可先看，
`p22_geometry.json` 是逐件逐线数据）。他的画法：

| 部位 | 他的画法 | 我们 065 的画法（要改掉的） |
|---|---|---|
| VIN(3) | 短线 → `+5V` 旗（(90,485)→(130,485) 全长 40） | 长导线进站 |
| 左 VOUT(2) | **自己的**短线 → 左侧 `VCC` 旗（(70,475)→(130,475)） | 与 pin4 之间一条翻顶实体线 |
| 右 VOUT(4) | **自己的**短线 → 右侧 `VCC` 旗，C1/C2 挂右侧短轨 | C8 挂右但轨太长 |
| GND(1) | 短线 → 地旗（(115,465)→(115,425)） | 远处长线下落 |
| 输入电容 C9 | 挂输入排线同高度，地旗在上 (110,525) | 远处大吊线 |
| 输出电容 C1/C2 | 挂 pin4 短轨下方，地旗就近在下 (245,420) | 同左 |

**规则提炼（岳两条原话 + 主代理对"远"的操作化，岳可在验收时否决）：**

1. **电源脚一律短线引出、以电源旗标收尾**（VIN/VOUT/地 都是）；旗标贴脚，
   横向 40–60 编辑器单位内，不许长跑线。
2. **同角色脚分布在体的异侧**（065 的点积判据，相对体中心点积 < 0）=「相隔较远」：
   **禁止画实体互连线**。每只脚各引一截短线，打**同名**旗标（电源脚用电源旗，
   非电源脚用文本 netlabel）——网靠名字并，不靠线并。
   **同侧同角色脚**仍可实体互连（短跳线），岳原话只禁「相隔较远」的。
3. 060② 的短接义务**形式变更**：电气义务不变（同名并网，岛表/网表/readability
   的 `netlist-partition-mismatch` 读的是网表，不应因此误报——若误报，改规则实现，
   不许改回实体线）；图纸义务从「画线短接」改成「同名旗标并网」。
4. 065 的「输出电容挂与输入异侧的脚」**保留**，但挂法改贴脚短轨 + 就近地旗
   （参照他 C1/C2：pin4 出来 15–25 单位即下挂，地旗在同一簇正下/正上 10–30）。
5. 他示例里输入电容挂**上**（地旗在上）是因为输入排线与旗标同高度——
   这是「轨道直且短」的结果，不是新的硬性方向规定，别过拟合。

## 追加裁决（岳看 P23 落图后补的两条，优先级高于 064 方向罗盘）

岳原话：「P23 5V部分为什么不给旗标？还有旗标一定要竖直摆放不能平放影响观感。」
主代理已渲染 P23 放大亲验，两条都属实：

6. **每条电源网在模块边界必须有电源旗，不能只打文本 netlabel**。
   P23 现状：VIN(3) 排线左端只有横向 `5V0` 文本，没有 Power-VCC 旗——而岳 P22
   手绘示例输入侧是有 `+5V` 旗的（(90,485) 短线端）。069 新逻辑给远脚打了标，
   但输入轨 5V0 漏了旗。**凡电源网（VCC/3V3/5V0/…）在模块内至少出现一颗电源旗**；
   只有文本没有旗 = 缺陷。
7. **旗标一律竖直，禁用 90/270**。P23 右端 `3V3` 旗是平放的（064 罗盘对水平
   stub 旋了 90°）——岳要求旗标姿态与 stub 方向**解耦**：stub 水平时，在端点拐
   一小段竖线（约 20–40 单位），旗挂竖线端：电源旗 rot 0 朝上、地旗 rot 0/180
   按 064 分家表（上挂/下挂）但**只许 0 或 180**。对照 P22 手绘：所有 Power-VCC
   rot=0，所有 GND rot=0/180，**没有一颗 90/270**；他的 VCC 旗 (70,505) 就是
   竖线降到 (70,475) 再水平进脚。064 的分家表（gnd/rail 偏移、旗种）保留，
   **方向映射改成恒竖直**——这是本条与 064 的张力点，以本条为准。

落地触点预判（交卷时以实际为准）：旗标落位逻辑里 ①补「电源网必有旗」的兜底；
②旗标 rot 计算去掉 90/270 分支，水平 stub 端点加竖向拐点线段。
测试要加：电源网无旗 → 缺陷检出；水平 stub 上的旗 rot ∈ {0,180}；
变异（强行 90 旋转 / 漏电源旗）→ 新测试必须红。

**落坑记录（v2 交卷后确认，主代理授权扩界）**：裁决 6 在模块层落地后，页级
`pagecompiler._net_style`/`_is_bus` 把成员数 ≤ high_fanout 的电源网判成 label 风格，
`_port` 随之把模块画好的旗连引线删掉——P23 上 5V0 仍只剩文本。裁决 6 原文是
「凡电源网至少一颗旗」，页级也应如此。主代理裁定走**方案 A**：`_is_bus` 改为
电源网一律按旗陈述（不再按扇出门限降级成 label）。**本批边界扩到
`pagecompiler.py` 的 `_is_bus` 一处与其测试**。连带 056/057 的 8 个页级场景
会以「label→flag」这一类移动，逐叶申报即可；出现其它类移动 = 停下报告。
（方案 B「页上 label 与旗并存」留作岳否决 A 时的后备。）

## 追加裁决二（岳看 P23 v3 渲染后补的两条）

岳原话：「3V3的旗标标识和5V的导线重合了，然后有了旗标就不要反复标注网络标识了。看着很乱啊」

8. **旗标整体（glyph + 竖引线 + 文字）不得与别网导线重合或贴近到视觉相碰**。
   P23 v3 实测：pin2 的 3V3 旗（页坐标 stub `[100,730→110,730]`，旗挂 (100,730)）
   与 5V0 轨 `[110,740→50,740]` + 竖引线 `[110,740→110,765]` 相邻——旗 glyph 下缘
   贴上 5V0 横轨、旗文字与 5V0 竖引线并排相挤。v2 的「锚点不得落在别网的脚/线上」
   只查了锚点一个点，不够：**要按整颗旗的包围盒（glyph 盒 + 文字盒，含少量 margin）
   对所有别网导线做避让**；被占就沿轨继续走（`_walk` 加长）或换侧，找不到空位
   宁可走远也不许贴上。
9. **有旗标的网，导线不再重复标注网络文本**。旗本身带名，v3 渲染里每根 5V0/3V3/GND
   导线旁还各有一份绿色网名文本——重复且乱。规则：**网在局部有旗 → 该网导线一律
   不落网名文本**；只有无旗的信号网保留 netlabel（TAP 那种）。先定位网名文本的
   来源（我们写进导线属性的还是宿主自动显示），把有旗网的文本通道关掉。

测试：旗盒与别网导线相贴 → 检出/移位；有旗网的导线无网名文本、无旗信号网文本保留；
变异（关掉避让 / 恢复重复标注）→ 新测试必须红。24 场景审计：预期大批「有旗网
导线文本消失」+ 少量旗移位两类移动，逐叶申报；其它类移动 = 停下报告。
E1 仍落 P23（不开新页），v4 前缀证据。
