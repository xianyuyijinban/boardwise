## 缺陷（审计原文要点）

`src/boardwise/core/values.py:645-653`（连同 `:153`、`:156-163`、`:683-690`）：
`_mid_letter_readings` 无条件剥「前导封装尺寸码」并把尾数截到 3 位——对 **MPN** 是对的，
对板子 **Value 字段**是错的（该路径自己的成文规则："No vendor prefix to guess at, so the
run itself is the mantissa"）。阻值被一条更早的纯数字语法护着，**容值没有**，所以只有容值断：

```
parse_capacitance_farads('160nF') -> 1.6e-07      # 读得出
parse_capacitance_farads('160n')  -> None         # 拒读
_without_leading_size('160')      -> ''           # 尺寸码把尾数吃了
```

**54 个不可读拼写**（全 metric+imperial 尺寸码 × p/n/u 三字母）：
`105p/n/u 160p/n/u 188p/n/u 201p/n/u 321p/n/u 322p/n/u 451p/n/u 453p/n/u`
`01005p/n/u 0201p/n/u 0402p/n/u 0603p/n/u 0805p/n/u 1206p/n/u 1210p/n/u 1812p/n/u 2010p/n/u 2512p/n/u`

最扎心的一条：`parts.quantity_slug('160n')` 返回 `'160n'`——**货架自己的规范拼写**
值解析器读不了；规则拿到不可读值就整件跳过 ⇒ 一颗 160nF 去耦电容对去耦规则**隐身**。
