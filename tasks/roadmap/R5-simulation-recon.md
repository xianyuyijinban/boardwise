# R5 → 远景：SPICE 仿真通路侦察（只侦察，不实施）

主题：岳说过「后面可能要包括一些仿真，SPICE 本身接近开源」。这个包只回答
「路在哪、通不通」，**不写功能代码**。

## 要回答的问题

1. **立创侧**：立创 EDA Pro 的仿真导出有什么（netlist 导出？仿真结果文件？
   宿主 API 有没有仿真相关调用）？证据：connector 动作表 + 宿主文档/实测。
2. **ngspice 通路**：本地跑 ngspice（开源 SPICE）——从 boardwise 的原理图模型
   生成 SPICE netlist 的可行性：器件模型从哪来（货架条目的 spec 字段？）、
   电源/地/探头怎么映射、哪些电路拓扑值得先支持（建议：RC 滤波、分压、
   电源轨上电时序这类审查能交叉验证的小题）。
3. **审查交叉验证的雏形想法**：规则引擎算出期望值（如 `param-rc-cutoff` 的
   截止频率），仿真跑出实际值，两者对拍——这是「审查+仿真」的最小价值闭环。
   评估这个闭环的数据链路缺什么。

## 产出

《仿真通路侦察报告》落 `outputs/R5/`：三问各自的结论 + 证据 + 「值得做/不值得做/
先攒着」的建议。报告里每个结论都要有可复核的来源（命令、读数、文档链接）。

## 红线

- 只侦察：ngspice 装隔离环境（venv/独立目录），不装全局、不动系统。
- 不写 boardwise 功能代码；若侦察中顺手修了 bug，单独小 PR。
- 结论不许乐观估计——「不知道」就写「不知道，下一步实验是 X」。
