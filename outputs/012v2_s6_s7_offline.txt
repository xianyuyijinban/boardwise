三、§六 export.fab 实现要点
================================================================================
签名： export.fab
        params { pcbUuid?, outDir, vendor?='generic', gerber?{...}, bomTemplate?,
                 timeoutMs? }   —— timeoutMs 每文件截止（200..600000，默认 60000）
        返回   { vendor, project{uuid,name}, pcb{uuid,name}, outDir, generatedAt,
                 encoding:'base64', files:[{role,name,mime,bytes,data,sourceName}],
                 manifest{...}, failed:[{role,reason}], partial, note }

1) 三件套一次出齐 + manifest：gerber(role=gerber) / 坐标(role=pick_and_place) / BOM(role=bom)，
   manifest 内容 = schema(boardwise.fab/1) + generatedAt + vendor(+summary) + project + pcb +
   outDir + preset（实际发出的全部参数，含 BOM 15 列）+ files（清单/字节数）+ failed + notes。
   落盘侧（CLI）再补 outDir 解析路径与 written[]（stat 实测字节）。
2) vendor 预设：只实现 generic ——
   gerber:  colorSilkscreen=false（彩色丝印是"嘉立创专用文件"，通用板厂不要）、unit='mm'、
            digitalFormat {4:5}、other{metallicDrilling:true, nonMetallic:true, drillTable:true,
            flyingProbe:false}；layers/objects **故意不写**（声明默认即编辑器"一键导出"：
            板内真实使用的层 + 钻孔层，写死一份清单在没上机前只能是猜）。
   P&P:     fileType='csv', unit='mm'
   BOM:     fileType='csv', template=params.bomTemplate ?? undefined,
            filterOptions=[Add into BOM=yes, Convert to PCB=yes]（声明自带示例的两条规则）,
            statistics=[No., Quantity]，columns=15 列全列，property 由 columns 派生
            （一处定义、两处使用，不可能互相矛盾）。
   捷配：留**配置位**不实现 —— FAB_PENDING_VENDORS.jiepei，报错文案区分"占位待样例"与"拼错"。
3) 落盘路径（判定依据，不是省事）：类型包只声明 SYS_FileSystem.saveFile(fileData, fileName?)，
   **无目录参数**（走浏览器下载/Electron 保存对话框），无法兑现 outDir。故沿用 export.render
   的可靠路径：连接器回 base64，调用方（daemon 侧 CLI）落盘。outDir 仍为必填参数并写进 manifest，
   使磁盘上那份 bundle 自己说得出"原本要放哪"。
4) 守卫与诚实结果：
   - pcbUuid 给了但与焦点 PCB 不符 → PAGE_MISMATCH（制造接口导出的是**前台那块板**；未导出任何文件）；
     未给 pcbUuid → 用焦点板并在返回/manifest 里写明 uuid+name；没有 PCB 打开 → CONNECTOR_ERROR（不猜）。
   - 命名空间或三个声明方法缺失 → NOT_IMPLEMENTED（结构性失败，报出是哪一个）；
   - 单个文件被拒/返回 undefined/空文件/超时 → failed[] 逐文件记录，其余照回（partial:true）；
     三个全丢 → CONNECTOR_ERROR（空 bundle 不是 bundle）；
   - 每个导出调用各有 deadline（raceHostCall，默认 60s/文件）：宿主吞掉入参时 promise 永不 settle，
     这是 export.render 实测过的形态，不能让动作槽被占死。
5) 文件名：宿主的 File.name 优先（它才知道 gerber 是不是 zip），否则 `fab_gerber`+（zip 魔数→.zip）、
   `fab_pick_and_place.csv`、`fab_bom.csv`；名字里的路径分隔符在连接器侧先剥掉，写盘侧再验一次。
6) CLI 落盘器（src/boardwise/cli.py）：
   `boardwise bridge export-fab --out DIR [--pcb UUID] [--vendor generic] [--gerber JSON]
    [--bom-template NAME] [--timeout-ms N]`
   - _write_fab_bundle(payload, out_dir)：纯文件操作（无需 daemon 即可测）——文件名必须**单段路径**
     （`../x`、`sub/x`、`.`、`..` 一律拒绝，不做静默改名）；非 base64 / 空数据拒绝；
     每个文件写后 stat 实测字节数，与连接器声明的 bytes 不一致 → manifest.byteCountMismatch + 退出 1；
     manifest.json 最后写、并补 outDir/written[]。
   - 退出码：0 全齐；1 动作失败 / 写入失败 / **残缺 bundle**（已到的文件保留在盘上，缺的在 stderr 点名）；
     2 daemon 不可达或 --gerber 非 JSON。

四、§七 lib.recommend 实现要点
================================================================================
签名： lib.recommend
        params { query? } | { pageUuid, ref }  二选一（同时给/都不给 = BAD_REQUEST），
               topN?（1..20，默认 5）, allLayers?, timeoutMs?（每页搜索截止 200..120000，默认 20000）
        返回   { source, query, ref, component, target, topN,
                 layers:[{layer,api,called,args,hitCount,pagesFetched,reason?|error?}],
                 returned, shown, candidates[...], 'stock/price', readOnly, placed, note, notes? }

1) 逐层降级（本层命中即止，被跳过的层**显式标 called:false + 原因**，"没找到" 与 "没跑" 绝不混同）：
   L1 exact      searchByProperties({partNumber, partCode})  —— 声明里的两条精确通路
   L2 properties searchByProperties({value, footprintName})
   L3 keyword    search(keyword)
   每层 itemsOfPage=5（"每层 Top5"）、页码上限 3（"分页上限 3 页"，含"整页就继续翻、短页即止、
   够 topN 即止"三条停止条件）；allLayers:true 则跑满三层并合并去重（同 device 以最早一层为准）。
2) searchByProperties 缺失是**降级不是错误**：类型包标注 "ADD since EDA v4"，v3.2 宿主上很可能没有；
   缺失时 L1/L2 标 unavailable + 原因，L3 照跑，notes 里顶层再说一次。
   lib_Device 整个缺失、或所有层都抛异常 → NOT_IMPLEMENTED / CONNECTOR_ERROR（"搜不了" ≠ "没搜到"）。
3) 位号路径：guardPage(pageUuid) → 焦点页组件枚举（sch_PrimitiveComponent.getAll）→ 位号匹配
   （getState_Designator → OtherProperty.Designator 兜底），读出现有 value/MPN/LCSC/封装/供应商封装；
   焦点页与 pageUuid 不符 → PAGE_MISMATCH（没有跨页查找 API，宁拒不错答）；位号不存在 → NOT_FOUND
   （detail 带本页位号清单）。query 路径：C+数字 视为 LCSC 编号走 partCode，其余字符串同时当
   partNumber 与 value（"SS34"这种真实 MPN 两个字段都认），每层 args 原样回显。
4) 排序与输出：JLCPCB Part Class —— Basic(0) < Preferred(1) < Extended(2) < 未知(3)，
   同级再看封装是否吻合、再看来自哪一层；TopN 默认 5。字段 name/lcsc/mpn/封装/
   JLCPCB Part Class/datasheet/deviceUuid+libraryUuid(+symbolUuid/footprintUuid)。otherProperty 的键名
   做"去空格/下划线/大小写"归一后匹配，库项先读普通属性再读 getState_*（两种形态都实测存在过）。
5) 只读：输出固定 readOnly:true / placed:false + 落座指引（sch.place_component /
   sch.set_component_attribute）；**无库存价格字段**（类型包没有），固定标注 `"stock/price": "以商城实时为准"`。
