--- 项2 lib.recommend query 路径 ---
证据：outputs/013_lib_recommend_SS34.json、013_lib_recommend_FRC0805J471.json、

附加判别（同一只读动作，用于分辨"不存在"与"匹配不到"）：
  query="C8678"       exact {partCode:"C8678"} called=true hitCount=0；
                      properties called=false（reason: neither a value nor a footprint name is known）；
                      keyword {keyword:"C8678"} hitCount=2
  query="SS34_C8678"  exact {partNumber:"SS34_C8678"} 0；properties {value:"SS34_C8678"} 0；keyword 1
结论（事实）：lib_Device.searchByProperties 在 3.2.186 **存在且可调用**（typeof=function；
  三种属性集都给 called=true、无 error 字段、返回数组长度 0）；但 try 过的四种属性集
  （partNumber=SS34 / value=SS34 / partCode=C8678 / partNumber=SS34_C8678）全部 0 命中，
  而同名 keyword 层每次都能命中（5 / 1 / 2）。即 searchByProperties 是"在但不匹配"，
  本宿主上 exact 与 properties 两层实质空转，全靠 keyword 层出货。
未确认项：无法区分"宿主忽略这些属性键"与"第 6/7 位实参（pageSize, page）位置不对"——
  lib.recommend 只按固定位置传 (properties, undefined×3, 5, page)，没有通道换参数重试。
hitCount=5 的语义：RECOMMEND_PAGE_SIZE=5（connector/src/actions.ts:4098），同 keyword 用
  lib.device.search 不传 pageSize 时 returned=10（宿主默认页 10）——所以 keyword 的 hitCount
  是**按请求页大小截断后的条数**，不是匹配总数（topN=5 也是停止条件之一）。
候选字段形状（lib.recommend candidates[]，每项 17 键）：

  layer 取值＝该候选首次出现的层名（"keyword" / 更早的 "exact"/"properties"），
  layerIndex 为层序（exact=0, properties=1, keyword=2）。

=== 真机新事实（与离线预期不符 / 离线没写清楚的）===
N1 searchByProperties 在 3.2.186 **存在但四种属性集全部 0 命中**（离线只备了"缺失则降级"一条路，
   没有"在但不匹配"这条；docs/bridge.md:1050 把"是否存在"列为待真机settle的问题——现在答了：
   存在，但不干活）。keyword 层是唯一实际出货的层。
N2 keyword 层 hitCount=5 是页大小截断值，不是匹配数（同 keyword 直查返回 10 条）。
N3 document.current.project 在真机上是 {}，与 doc.list 的 /test 不同口径（同一宿主调用的两种读法）。
N4 库项是扁平对象，无 item.symbol / item.footprint 子对象；代码里的 footprintUuid/symbolUuid
   回退在真机上是**必需路径**（离线看着像冗余）。
N5 库项 otherProperty 存在字段级空缺（Manufacturer/Datasheet/description/imageUuid 全空、
   classification uuid 为 null）——"读到空"与"读失败"在输出里是两回事，本批未见读失败。
N6 item 名与 MPN 可以不同（name="SS34_C8678"、mpn="SS34"、supplierId="C8678"）；
   第 4 个候选 name="SS34"（C9900023345）与 MPN 同名但制造商为空。
N7 doctor 的 project 行写 "5 页原理图"，其中的 5 = schematics[] 长度（含容器 schematic1），
   实际页数是 schematicPages=4。数值来自 projectRows 的 schematics[]，标签措辞偏松，非 FAIL。
N8 tabs[] 只有 Start Page 一个 tab，且 documentType=null、附带 keys[]——documentType 键名在本
   宿主上仍未定（离线已知，真机复现）。
N9 doctor 七项全绿、退出码 0，与离线预期一致（无差异）。connector 版本比对项真机 0.4.6==0.4.6。
