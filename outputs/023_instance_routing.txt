3. 语义决定（供复验）
================================================================================
- 两个 hint 同时给：instance 优先（实例精确到一条连接，工程名可能被多个窗口共用）。
  实现位置：daemon.route() 先解析 target_instance，命中即返回；未命中直接抛
  WINDOW_NOT_CONNECTED，**不再回落到 targetProject**（回落会让"我指名了窗口"变成"我指名了工程"，
  正是 018 测到的静默错窗写）。用例 test_an_instance_hint_wins_over_a_project_hint。
- window_for_instance() 先比 key、再比 instanceId，所以 `inst-x` 与 `inst-x~2` 各直达一条连接，
  既有的「同 id 取最长在线者」语义不变（未加后缀者即最老者）。
- 无 hint 单窗口直达、无 hint 多窗口 WINDOW_UNSPECIFIED、无窗口 NO_CONNECTOR：一个字节未变。
- 路由失败时错误帧不带 context（没选窗口就不宣称谁答的）；成功帧带应答窗口的实时 context。

================================================================================
4. --instance 下 update-connector 的 verified 语义（一句话）
================================================================================
等任一在线窗口（daemon `ping` 的 windows 表，daemon 自答、不需要路由）报到刚写入的版本即算
verified（exit 0）；若被指名的那个窗口仍以自己的 key 在线且报旧版本 → FAILED（exit 1）；预算内
两者都没读到 → UNKNOWN（exit 3）。探测不再用 sys.probe 打旧 instanceId —— reload 后该窗口以**新**
instanceId 重连，旧名字已不存在；不带 --instance 时行为完全不变（仍是 sys.probe 单连接回读）。
代价已写进 docs/bridge.md §8：该读法只能证明"某个窗口在跑新版本"，不能证明"就是那个窗口"——
两者在 id 更换后不可区分，故不做更强的宣称。
