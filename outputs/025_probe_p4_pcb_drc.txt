1. 边界一：不在 PCB 文档时**宿主 throw，不是 undefined**
--------------------------------------------------------------------------------
（任务书 §0 记的是「不在 PCB 文档时返回 undefined」——**类型包与真机不一致**，这条要更正。）
    [CONNECTOR_ERROR] pcb_Drc.check threw Error: 指定的主题消息在对应的画布内没有相关订阅.
      The declaration says the call reports nothing at all when no PCB is focused;
      the focused document here is b4298962367251c8 (page)
    detail: {path:"pcb_Drc.check", args:{strict:true,userInterface:false,includeVerboseError:true},
             focused:{uuid:"b4298962367251c8",type:"page"}, thrown:true, errorName:"Error",
             errorMessage:"Error: 指定的主题消息在对应的画布内没有相关订阅", elapsedMs:0}
宿主文案是消息总线口径（DRC 请求发布到 PCB 画布主题，原理图页上没有订阅者 → throw）。
connector 两种形态都处理（throw → CONNECTOR_ERROR 带焦点文档；真回 undefined 才走
`checked:false + reason` 那条）。**绝不把「没有 PCB 可查」报成「板子零错误」。**
顺带修掉一处文案 bug：宿主 message 自带 `Error:` 前缀，早先拼成 "Error: Error: 指定…"，
现已只在 message 不带前缀时才补 name（前后两次抓取都在 .tmp_025_p4_onsch.json /
.tmp_025_f_p4_boundary.json 里留证）。

4. 场景缺口（R3：不自行替代，如实报）
--------------------------------------------------------------------------------
任务书 P4 的兜底是「都没有就在 test 工程用 pcb.doc.new 建一页放两个器件一条线再跑」。
实测两件事：
  (a) test 工程**有** PCB 页（PCB1），不用新建——但它是**空板**：
      `pcb.readback` → {"kind":"pcb","components":[],"primitives":[],"componentCount":0}。
      （旁证：在原理图页调 pcb.readback 会 INTERNAL —— 宿主 `pcb_PrimitiveComponent.getAll`
      内部 `Cannot read properties of null (reading 'map')`，socket 栈落在 pro-api api.js；
      在 PCB 页调用则正常返回空数组。）
  (b) **当前动作集没有 PCB 放置能力**：ACTIONS 里只有 sch.place_*，PCB 侧只有
      readback / modify_primitive / delete_primitives / doc.new；宿主有
      `pcb_Document.importChanges`（原理图→PCB 导入变更）但**未注册**，也不在本批范围内，
      所以我**没有**为了凑场景去调它 —— 「两个器件一条线」的 PCB 场景这次没造出来。
  效果评估：即便空板，DRC 也给出了 **1 条真实错误**（Netlist Error / Import Changes：
  原理图有器件、PCB 没有 → 网表不匹配），于是批 3 需要的**逐条叶子形态已经拿到**；
  未拿到的只是「器件/坐标类错误（clearance/unrouted 等带 net/pos/layer 的叶子）」。
