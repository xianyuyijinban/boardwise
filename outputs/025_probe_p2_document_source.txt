3. 结构特征
--------------------------------------------------------------------------------
* 逐行一条记录，行格式 **`{"type":…,...}||{…body…}` + 行尾 `|`**，与 `.epru` 里
  `load_epru_text` 读到的记录流**同一套语法**（首行是 DOCHEAD）。
  逐行验证：35/35 行的 header 与 body 都能 `json.loads` 解析通过；34 行带行尾 `|`，
  最后一行不带（与 .epru 一致）。
* 记录类型直方图：
    P1（11,300 字符）：DOCHEAD 1（SCH_PAGE b4298962367251c8）、CANVAS 1、ATTR 32、COMPONENT 1
    P4（14,452 字符）：DOCHEAD 1（SCH_PAGE 362924e0e16ce90a）、CANVAS 1、ATTR 41、COMPONENT 2
* **只含焦点文档那一个 DOCHEAD**：没有 SYMBOL / DEVICE / SCH / META 文档，即页面引用的
  库文档不在其中（这决定了下面的等价性判定）。
* 头字段与导出流有差异：源里 DOCHEAD 头是 `{"type":"DOCHEAD"}`（无 ticket），
  ATTR 头带 `ticket`+`id`；导出件里 DOCHEAD 头带 `ticket`，且 ATTR/COMPONENT 的 body
  多出 `strikeout`、`zIndex` 取值不同（源:0 / 导出:null），源多一条 CANVAS 而导出件多
  META 与 LINE。

4. 与 .epru 记录流的等价性：**语法同、记录集不同、模型不等价**
--------------------------------------------------------------------------------
(a) 记录集（同一页 P1：源 vs 同一页在 getDocumentFile 导出件 `.epru` 里的段落）
    源           35 条：DOCHEAD 1、CANVAS 1、ATTR 32、COMPONENT 1
    导出件同页    37 条：META 1、ATTR 32、COMPONENT 1、LINE 3
    逐条按 (type, body) 精确比对：**0 条完全相同**（ATTR 逐条在 zIndex / strikeout 上不同）。
(b) 模型级（决定性判据）：把源文本原样封成 `x.epru` → zip 成 .epro2 → 走同一条离线管线
    P1：源→模型 0 器件 / 0 网；导出→模型 0 器件 / 0 网（P1 太小，分不出）
    **P4：源→模型 [('R2', footprint='', value='')]，nets 0
          导出→模型 [('R2', footprint='0603', value='')]，nets 2**
    差在两处，且都是「A2 直接顶替 A1 会静默丢信息」的形态：
      · footprint 丢失（'0603' → ''）——因为页面引用的 SYMBOL/DEVICE 文档不在源里；
      · 连通性归零（2 网 → 0 网）——同理，引脚/连线所属的库文档缺失。
(c) 结论：源 = **焦点页自身的实时记录流**（编辑器内存态序列化），
    导出件 = **保存态序列化 + 规范化（补 META/LINE）+ 被引用库文档 + 预览图**。
    两者同语法，但 A2 **不能**在模型级别等价替代 A1。

5. 附带确认
--------------------------------------------------------------------------------
* 源长度随焦点页变化（11,300 ↔ 14,452），且总在 reload/切页后与当前焦点一致 →
  它就是「当前文档」的源码，任务书 §0 里「格式是否等价 .epru 未证」这一条现在有答案：
  **同语法、非同一记录集**。

结论：**不能用**（作为 A2 顶替 A1）——同语法但只覆盖焦点文档、缺被引用库文档，模型级
会丢 footprint 与全部连通性（P4 实测 0603/2 网 → ''/0 网）；可用作单页记录流的原始查看
（诊断/对比用），不可用作审查模型的来源。
