      旧规则 = 归档字节相等；新规则 = 逐成员内容 sha256（文本成员 CRLF→LF）。

四、新的守卫语义（一句话）
--------------------------------------------------------------------------------
--check 把重建结果与提交夹具按**归档成员逐一比内容 sha256**（成员名集合必须相等；文本成员
先 CRLF→LF），不再比归档字节——环境压缩差异在新语义下根本不存在，内容漂移则精确报到
"<板>.<后缀> :: <成员名>"（成员缺失/多余同样报出）。

实现位置 reviewsets/injected/make_variants.py：
  TEXT_SUFFIXES / _normalise()        文本成员行尾归一（.epru/.json/.txt/.csv/.md/.xml）
  _content_digests()                  成员名 -> 内容 sha256；非 zip（.json 标注集）取 {"":...}
  _drift_labels()                     比两个 digest 映射，报成员增/删/改
  _artifact_label()                   "fixed-base.epro2 :: CH340G.epru" 这种可读拼法
  check()                             组装：快照提交侧 digest -> 重建到 .tmp_variant_check -> 比
报错文案已改（不再说 "byte-identical"）：
  "regeneration drifted from the committed fixtures (member content differs; the
   deflate stream is not compared, issue #1): <列表>"
说明写进了模块 docstring 的第二条性质 + 新比对区段注释，均链回 issue #1。

测试侧：
  改名 test_regeneration_is_byte_identical -> test_regeneration_reproduces_the_committed_content
  改断言 test_check_reports_drift_without_rewriting_the_fixture：要求报文含
        "member content"、板名、"CH340G.epru"（只报文件名的旧断言已不成立）
  新增 3 条：
    test_the_guard_compares_content_not_the_compression_stream
        真跑 check()，但把写出改成 compresslevel=1；断言重建归档字节**确实**与提交不同
        （否则测试空转），同时 check()==0。
    test_drift_is_reported_member_by_member
        改一个成员内容 -> 只有该成员被判漂移；删一个成员 -> "<成员> (member missing)"。
    test_line_endings_are_not_content
        LF/CRLF 的 .json 与 zip 成员判一致（且两文件字节确实不同），同成员多一行仍判漂移。
