样本的可信度限制（必须一起读）
-----------------------------------------------------------------
这次 probe 只采到 test 工程当前页（P1）上的**唯一一个 sheet 图元**——test 工程的
P1..P4 四个页在磁盘导出里都只带自己的页框（每个 SCH_PAGE 文档 1 条 COMPONENT +
若干 LINE，见 outputs/016_incident_test2_page.txt 的同类观测），所以**没有真实电阻**
可以采样。也就是说：本文件没有"真实器件的 fields 里有没有 Value"的直接观测。

但问题（"够不够跑 param-value-mpn-match 单规则"）不依赖那一条观测，
有一条**结构性**的证据直接定死答案：

结论：不够 —— 复查口径取"另存新 .epro2 → 审查 --file 新文件"
-----------------------------------------------------------------
1) readback 的每行组件是**写死的键集合**，没有 value、没有 mpn
   （connector/src/actions.ts:619-627）：
       components.push({
         primitiveId: ...,
         designator: fields.Designator ?? null,
         name:       fields.Name ?? null,
         footprint:  fields.Footprint ?? null,
         supplier:   fields.Supplier ?? null,
         supplierId: fields.SupplierId ?? null,
         manufacturer: fields.Manufacturer ?? null,
         x, y, rotation, (net | layer),
         fields,
       });
   另有 `fields` 一条"40 个标量的快照袋"。所以：
   - footprint 有（独立键，去重值在 fields.Footprint）→ 有；
   - value  无独立键；mpn 无独立键 → 无。
   上表实测的 sheet 行印证：designator/footprint 都在，Value 不出现。

2) 即使真器件的 `fields` 袋里出现标量 `Value`，**mpn 也一定拿不到**，这才是判据：
   `snapshot()`（actions.ts:218-241）只走 `getState_*()` 取标量；对象一律降级成
   `{object: true}`。而 Value 与 Manufacturer Part 在宿主里位于
   **OtherProperty**（对象）内——本文件的实测行里 OtherProperty 正是
   `{"object": true}`。`param-value-mpn-match` 需要同时拿到 value 和 mpn
   （rules/params.py `_rows`：comp.value 与 comp.mpn），缺 mpn ⇒ 规则只能出
   UNKNOWN，复查永远不可能得到 resolved。故按 §九.5 走"不够"那条分支。

3) 顺带确认（与 §九.5 的另一半一致）：`sch.geometry` 能拿到 Value，但那是
   **活页**读，且走的是 `state.OtherProperty.Value`（core/changeplan.py:396-438
   `resolve_on_page`）——它够 apply 的前置比对，不够离线规则重跑。

定下的复查口径（波②）
-----------------------------------------------------------------
   apply → save → 请岳在编辑器"文件 → 导出 → 工程备份"另存一份**新的 .epro2**
   → `boardwise review --view schematic --file <新文件>`
