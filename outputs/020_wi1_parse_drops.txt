   + 新增私有 helper `_stats_for(parse_stats, path, meta)`：调用方给对象就用它（顺带补

     `if ... and run_number:` 改写成 `if current is not None and pin_open is not None:` +
     `if run_number: ... elif parse_stats is not None: parse_stats.pins_dropped_no_number += 1`。
     **返回值一个字节没变**（下面有 HEAD vs 改后逐模型比对）。
   + `build_pin_offsets(path, *, parse_stats=None)`：:518 的 `symbol_def is None` 分支计数。
   + `build_schematic_model(path, *, parse_stats=None)`：器件段（原 :784）与电源旗标段

   + `collect_symbol_details` 把它自己那个 stats 传进 `_collect_symbols`（局部对象，
     数字不外泄，只为"收集符号处一律计数"这一条不出现例外）。

3) src/boardwise/rules/i18n.py
   + `parse_drop_hint(pins_dropped, components_without_symbol) -> str`（中文文案；两项都 0 返回空串）。
     文案定稿（两项都非 0 时）：

     `_parse_drop_note(pins_dropped, components_without_symbol) -> str`（英文控制台 note；0 项不出现）。
     文案定稿（两项都非 0 时）：

     逻辑原样保留；两段都非空时按 `\n\n` 分开，各自成段）。

     `--md` 的中文摘要按需带提示。

覆盖范围（如实说明）
--------------------------------------------------------------------------
* schematic 视图（`--view schematic`）：两个计数都会填，note 会出。
* pcb 视图（`.epro2` 缺省）：**不填**。该视图的模型来自 PCB 文档
  （parsers/epro2_model.py），它根本不读 SYMBOL 文档 —— 那三条丢脚路径在这个通路上不存在，
  计数"恒 0"是结构决定的、不是量出来的。所以 `_load_model` 不往那里塞统计，
  `_parse_drop_note` 也不把 0 当作"没丢东西"的证据渲染（0 的项一律不出现）。
  这一点由测试 test_the_pcb_view_never_fills_the_drop_counters 与
  test_the_pcb_view_of_the_same_file_gets_no_note 钉住（同一份 llc 文件：schematic 报 14，
  pcb 一个字都不说 —— 在 pcb 视图里那句"覆盖不完整"会是假话）。
* `.enet` 输入：不经过本解析器，不涉及。
