## 与任务书设计的偏离（都在测试里可见）
1. hint 给定时若一个窗口都没连 → 仍是 NO_CONNECTOR（不是 PROJECT_NOT_CONNECTED）：此时"在线窗口
   清单"是空的，NO_CONNECTOR 的 "Is EasyEDA running…?" 比"该工程没开"更准确，也保住了 CLI/doctor
   既有的 NO_CONNECTOR 文案与退出码。
2. 同 instanceId 双活（3.2.175）：两条连接都保留，第二条 key 加 `~2` 后缀（WINDOW_KEY_SEPARATOR），
   于是出现 key ≠ instanceId 的行——status 与错误消息显示 key。这是"先 ambiguous 报错，人能看到"
   的实现方式，不是静默去重；审计 hello 记录里有 duplicateInstanceId 字段。
3. 只实现了 targetProject 与默认规则；未实现显式 windowId 直达（设计段没写，CLI 也没这需求）。
4. 额外两件（任务书未点名，但直接服务"AI 指哪打哪/可验证"）：
   a) 中继给 CLI 的 response/error 帧顶层带 context = 应答窗口的实时身份（旧连接器无 context 时，
      daemon 用 hello 得到的上下文填），调用方能自证"这活是哪个窗口干的"；
   b) 每条被转发的审计记录带 windowKey + projectName；disconnect 记录带该窗口最后已知的工程/页/routed。
5. 拆掉的东西：refuse_if_held / RejectionNotice / _announce_rejection / on_rejection / recent_rejections /
   ActiveConnector / active_instance()。保留两个"退役名"：ErrorCodes.CONNECTOR_ALREADY_ACTIVE（标注退役，
   还在 §5 表里）与模块常量 AUDIT_CONNECTOR_REJECTED（不在 __all__）——理由：旧日志/在野连接器读得到，
   删掉会让"查无此码/查无此记录"变成新的困惑；测试 test_the_refusal_machinery_is_gone_and_its_code_is_retired
   钉住"机制不许回来"。
6. ping 的 activeInstance / recentRejections 被 windows[] 取代，没做兼容层（同一仓库同版本，无跨版本读者）。
