问题（020 审计 §3）
--------------------------------------------------------------------------
`sys.self_update` 的 `newVersion` 是**回显入参**（self-update.ts 只写 DB 就返回），CLI 打印
`ok: old->new` 即 return 0；reload 排了 500ms 定时器后**无任何回读**。旧 build 照旧应答每一个动作，
所以"更新失败"和"更新成功"在输出上完全一样 —— 假成功窗口。单测把这个契约钉死
（test_bridge_cli.py 原 :523-541，断言含 "0.4.2 -> 0.4.3" 与 "reloading"），任务书允许升级它。

改了什么（src/boardwise/cli.py）
--------------------------------------------------------------------------
+ 三个计时常量（**在调用时读取**，不是绑进默认参数 —— 这是让测试能把时钟缩到 0 的接缝）：
    UPDATE_VERIFY_INTERVAL_S = 1.0    轮询间隔
    UPDATE_VERIFY_BUDGET_S  = 30.0    总预算
    UPDATE_RELOAD_MARGIN_S  = 0.5     在回复自带的 reloadInMs 之上多等的余量
+ `_running_connector_version(BridgeClient, BridgeError, port, token)`：一次读。
  新开一条 CLI 连接 → `sys.probe` → 取 `connector` 字段（与 doctor 读运行中版本同一个读法，
  cli.py:4883-4898 那套）。没 daemon / 没连上 / 还在 reload 都是 `None`（"还没回来"），不报错。
+ `_await_running_connector_version(..., *, reload_ms, interval_s, budget_s, margin_s)`：
  先睡过 `reload_ms + margin_s`，再每 `interval_s` 读一次，直到 `budget_s` 用完；
  读到版本就返回，超预算返回 None。
  三个计时参数是**必填关键字参数**（不给默认值）：调用方在运行时查模块常量，
  这样测试缩时钟时不会踩到"import 期已绑定的 30 秒默认值"（这个坑真实踩过一次：超时用例跑了 29.8s）。
+ `_cmd_bridge_update_connector`：
  写完 → 若 `--no-verify`：照旧打印 "reloading…" 并 return 0；
  否则读回运行时版本并三分支：
    匹配        → `  verified: running connector is now X.Y.Z`  → exit 0
    不匹配      → stderr `FAILED — the write stored X but the connector answering is Y: the update
                  did not take effect (… bridge status names the holder)` → exit 1
    超时未回读  → stderr `the connector did not come back within 30s — the state of the write is
                  UNKNOWN, not failed: …` → exit 3
+ `--no-verify` 参数（帮助文本写清：恢复 020 之前的行为，exit 0 即使旧 build 还在应答）。
+ docstring 写清三分支与"为什么不立刻读"。

**先等过 reload 窗口再读**是这个阶段最容易写错的一处：reload 有 500ms 定时器，
立刻探到的是**将被替换的旧 build**，把那个读结果当"不匹配"就会把一次好更新报成失败
（exit 1）。所以第一次读发生在 `reloadInMs + 0.5s` 之后，且有一条专门的顺序测试钉住这一点。

期望版本取自 `params["version"]`（= `connector/extension.json` 的 version，除非传了 --version），
与 doctor 的比对面完全同一个定义。注意：`extension.json` 与 `package.json→build.mjs 注入的
`__BOARDWISE_VERSION__`` 是两个文件（020 审计 §3 附注），两者若漂移，这里会像 doctor 一样报不匹配 ——
行为一致，不额外发明第二套判据。
