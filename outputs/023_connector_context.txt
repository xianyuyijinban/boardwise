设计要点
--------
1. 帧顶层，不在 result：`context` 是 `data` 的兄弟键，`data` 一个字节未变
   （单测断言 `answer.data` 深比较 + `'context' in answer.data === false`）。
2. 唯一收口点：`Transport.reply(frame)` —— 成功帧、ActionError 帧、INTERNAL 帧、
   以及"请求帧没有 action"的 BAD_REQUEST 帧全部经它发出，`reply` 里一次
   `withContext(frame, await readResponseContext())`。不是四处撒胡椒粉。
3. 读取时机：在 action handler **之后**读（`doc.open`/`doc.focus` 之后必须报告新文档）。
   每次响应现读，绝不沿用上一次（单测 pin 住两次响应两个不同 context）。
4. 防抛/超时壳：整段读取由 transport 侧 `readWithDeadline(read, ms)` 包住，
   `Promise.race` + 1500ms（与 021 hello 身份同一个值、同一个模式，
   `RESPONSE_CONTEXT_DEADLINE_MS`），抛异常/永不 settle 都只等于"没有 context"，
   绝不拖住已经执行完的动作响应；测试把 deadline 缩到 20ms 验证释放。
   读到的字段在帧侧再做一次词表清洗（`withContext` 内 `contextFields`）：空串、
   非 sch/pcb 的第三种词、非字符串一律变成"没有这个键"。
5. 词表：pageType ∈ {"sch","pcb",null}，与 `document.current` 的映射逐字一致
   （schematic/page -> "sch"，pcb -> "pcb"）。`null` 是"读到了一份文档但它两种都不是"
   （symbol 编辑器、home 页）；读不到文档 / 读到宿主占位 uuid "0" 时**省略**这两个键。
6. 无 reader 的旧构建：帧与 023 之前完全一致，不含 `context: {}`。

与任务书的理解/偏离
-------------------
1. `pageType: null` 的触发条件（任务书只给了类型 `"sch"|"pcb"|null`）：
   取"有文档但既非原理图页也非 PCB"为 null；"没有任何文档 / 读不到"则**省略键**。
   理由：任务书两处要求"读不到的键省略"，而 null 需要是一个真实读数才有意义；
   daemon 侧 merge 语义下 null 与省略等价（不改已知值）。
2. 错误帧也带 context（任务书说"每个 action 响应帧"）：失败的动作同样要说明是哪个
   窗口失败的，而这正好是调用方最需要窗口身份的场合；实现上是同一个收口点。
